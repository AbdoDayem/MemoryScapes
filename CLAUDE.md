# CLAUDE.md

MemoryScapes turns a video (or panoramas) plus an audio recording into a walkable Gaussian-splat "memory" with a spatial soundscape generated by SATIE (Attractor Labs). Memories can be published to a shared globe. Full design: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Read it before making structural changes.

## Status

Partly a scaffold: most API endpoints still return `501`. In the workers, the visual stages (`ingest`, `poses`, `splat`) and the audio stages (`separate`, `localize`, `soundscape`) are implemented and tested; `publish` writes the manifest for private memories (no privacy pass yet). The API serves `GET /memories/:id` and its files; the web viewer (`/memories/[id]`) renders the splat with Spark and plays the audio. `python -m memoryscapes_workers.run` runs the whole pipeline on one uploaded video (each stage in its own process), and the debugger's upload page drives it. Follow the build phases in `docs/ARCHITECTURE.md` § 9. The MVP is video → COLMAP → gsplat → web viewer, with private memories only. Stage data contracts are in `services/workers/README.md`.

## Layout

| Path | What lives there |
|---|---|
| `apps/web` | Next.js 15 + React 19 + TypeScript client. Routes: `/` globe, `/upload`, `/memories/[id]` viewer. Sound is always SATIE's: `src/components/audio/SatieAudioEngine.ts` plays the SATIE soundscape with `satie-runtime`. |
| `services/api` | FastAPI (Python 3.11+). Entry `app/main.py`, routers in `app/routers/`, Pydantic models in `app/models.py`. |
| `services/workers` | Processing pipeline. DAG in `memoryscapes_workers/pipeline.py`, one module per stage in `stages/`, SATIE adapter in `providers/soundscape.py`. |
| `packages/manifest` | Memory manifest contract: `memory.schema.json` (source of truth) + `index.ts` (TS mirror). |
| `infra` | `docker-compose.yml` (Postgres/PostGIS, Redis, MinIO) and `db/init.sql` (schema). |
| `tools/debugger` | Local Vite + React + three.js UI for inspecting stage outputs and checking that the audio and splat pipelines agree. Standalone package (not an npm workspace). |
| `deploy` | Running the site on the Windows PC: `setup.py` (venvs, CUDA torch, models, web build, `.env`) and `serve.py` (API + web, restarted on failure), with `windows/*.cmd` launchers. Guide: `docs/DEPLOY_WINDOWS.md`. |
| `docs` | `ARCHITECTURE.md`, a styled `architecture.html`, `SPLAT_OUTPUTS.md` (what the poses/splat stages must write), and `DEPLOY_WINDOWS.md`. |

## Commands

```bash
npm install && npm run dev:web   # web app on :3000 (globe homepage, upload, viewer)
cd services/api && uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -e ".[dev]"
cd services/api && .venv/bin/uvicorn app.main:app --reload   # API on :8000, SQLite at services/api/data/ (no Docker)
cd services/api && .venv/bin/python -m app.seed               # demo memories for the globe
cd services/api && .venv/bin/python -m pytest                 # API tests
npm run infra:up                 # later: Postgres/PostGIS, Redis, MinIO (Docker); nothing uses them yet
cd services/workers && python -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"   # core + tests
cd services/workers && .venv/Scripts/python -m pytest                                            # worker tests
cd services/workers && pip install -e ".[audio,visual,satie]"   # model backends + SATIE MCP client
# Windows + NVIDIA: gsplat must be built from source once (cuda_env.cmd); see services/workers/README.md "GPU splat training on Windows"
cd services/workers && memoryscapes-worker demo                  # synthetic video -> ingest -> poses -> splat (local)
cd services/workers && memoryscapes-worker satie-login           # once per server: SATIE sign-in, saved to .satie/ (git-ignored)
deploy\windows\setup.cmd && deploy\windows\start.cmd            # the deploy PC: set up, then run the site on :3000 (docs/DEPLOY_WINDOWS.md)
cd services/workers && memoryscapes-worker run demo --stages publish   # manifest; then the API + dev:web -> /memories/demo
cd services/workers && .venv/Scripts/python examples/run_example.py   # audio example memories -> examples/out/
cd tools/debugger && npm install && npm run dev                      # debugger on :5178, with video upload (MEMORYSCAPES_DATA=<root> for other data)
cd tools/debugger && npm test                                        # debugger parser/check/API tests
```

## Rules for working in this repo

- **The manifest is the contract** between pipeline and viewer. If you change its shape, update `memory.schema.json` and `index.ts` together, and bump `version` semantics carefully, because old memories must keep loading.
- **One coordinate frame.** Splat, audio source positions and geolocation share one metric world frame (`coord_frame.units = "meters"`). Don't introduce unscaled or per-asset frames. The debugger's alignment check enforces this between the splat and the poses.
- **Stage outputs are a contract with other teams.** The splat side is specified in `docs/SPLAT_OUTPUTS.md`. When you change what a stage writes, update that doc or `services/workers/README.md`, plus `tools/debugger/src/lib/types.ts` and its checks.
- **Stages are idempotent** and write only under `{memory_id}/{stage}/` through `ctx.storage` (`StageContext.key`). A stage must be safe to re-run.
- **Model backends are injected.** Stages take tagger/separator/detector/provider arguments, and `backends.py` builds the real ones from env. Tests use fakes and synthetic scenes with known ground truth; keep it that way so tests never need torch or network.
- **SATIE stays behind `SoundscapeProvider`** (`providers/soundscape.py`, MCP via `providers/mcp_transport.py`). Don't call it from anywhere else. `SOUNDSCAPE_PROVIDER` defaults to `satie`; `stub` is for tests and offline work only (the memory then has no sound). Store raw provider output so audio can be re-rendered.
- **SATIE spends money.** Never raise `SATIE_MAX_CENTS` or enable `SATIE_ALLOW_GENERATION` without the developer asking. Keep `requestKey` stable for the same script so retries resume instead of re-buying.
- **SATIE always does the spatialization, on the client.** The viewer plays sound only through `satie-runtime`, with each localized source bound as a host at its position and the camera as the listener. Don't add another spatializer or a fixed binaural render. Keep the "Sound by SATIE" badge (its licence requires it).
- **Keep heavy ML dependencies optional** (`[visual]`, `[audio]` extras) so the API and CI stay light.
- **Privacy before public.** Nothing becomes `public` without the publish stage's face/plate blur and speech check.
- Never commit `.env`, real credentials, or pipeline outputs (`*.ply`, `*.spz`, `data/`).
