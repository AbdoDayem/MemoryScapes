Memory Globe Architecture

A web app that turns a video (or a set of panoramas) plus an audio recording into a "memory": a Gaussian splat you can walk through, with the recording separated into sources, placed in 3D, and rebuilt into a soundscape by SATIE. Public memories live on a shared globe.

Overview

Three parts, one shared coordinate frame

Processing pipeline

A long-running, GPU-heavy workflow. Each stage is idempotent and writes its output to object storage, so a failed run resumes where it stopped.

Memory package

A versioned manifest that places the splat, the audio sources and the metadata in one metric world frame. It is the contract between pipeline and viewer.

Viewer and globe

Run in the browser and stream compressed splats and audio stems from a CDN. Spatial audio is rendered at runtime, so it follows the listener.

Processing pipeline

From upload to memory

A workflow DAG. Every stage writes to s3://memories/{id}/{stage}/. The visual and audio branches run in parallel and meet at localization, which needs both camera poses and scene geometry.

Dashed box marks the external dependency. The dashed edge carries splat assets straight to publish; a low-iteration preview splat can be published early.

STAGE · INGEST

Ingest

  • Demux with ffmpeg. Keep the original audio channel layout and sample rate.
  • Pick 150–400 keyframes by sharpness (Laplacian variance) and parallax.
  • Panoramas: split equirectangular frames into cubemap crops, or use spherical-camera SfM (OpenSfM, COLMAP rigs).
  • Read GPS and capture time from EXIF or container metadata for the globe pin. If missing, the user places it.
STAGE · VISUAL

Camera poses

  • Quality path: GLOMAP or COLMAP.
  • Fast path: feed-forward VGGT or MASt3R-SfM for poses and dense points in seconds to minutes.
  • Estimate metric scale from monocular metric depth, or later from phone IMU/ARKit. Audio distance falloff only sounds right in meters.
STAGE · VISUAL

Gaussian splat

  • Train with gsplat (Nerfstudio Splatfacto) on an L4/A10G/A100-class GPU. Minutes per scene.
  • Remove floaters and crop to the trajectory's convex hull.
  • Compress to .spz or SOG: tens of MB instead of hundreds for raw .ply.
  • Produce 2–3 LOD levels for progressive streaming.
STAGE · AUDIO

Separation and labeling

  • General sound events: query-based separation such as AudioSep or SAM-Audio-style "separate X" prompts.
  • Speech: dedicated enhancement and diarization. Music: HTDemucs.
  • Tag each stem with CLAP or BEATs. The residual becomes the ambient bed.
STAGE · AUDIO · HARDEST PART

Source localization

Most uploads are mono or stereo from a moving phone, so direction can't be measured directly. Use three strategies in order:

  1. Audio-visual grounding (default). Match each stem's label to objects detected in the frames (Grounding DINO + SAM), then lift them to 3D with camera poses and splat depth. Birdsong goes to the tree, voices to the people.
  2. Multichannel DOA. With stereo, ambisonic or multi-mic audio, run SRP-PHAT or MUSIC per window and triangulate bearings across the known camera trajectory.
  3. Fallback. Stems that can't be placed become diffuse sources or join the ambient bed around the listener.

Output per stem: {stem_id, label, position | trajectory, spread, confidence, gain} in the splat's world frame.

STAGE · EXTERNAL

SATIE integration

  • Wrap SATIE behind a SoundscapeProvider adapter so its API can change and development can use a stub.
  • Input: stems, positions, labels, ambient bed, scene bounds, optional mood prompt.
  • Prefer an object-based scene back, so spatialization happens on the client during free navigation. If only rendered audio is available, ask for ambisonics (FOA/HOA), which still rotates with the listener.

SATIE's actual input and output formats are unverified. Confirm them before fixing this contract.

STAGE · PUBLISH

Privacy and publish

  • Before going public, blur faces and license plates in source frames and retrain, or mask them in the splat.
  • Optionally detect and mute or flag speech so private conversations don't reach the globe.
  • Render a thumbnail and a 5-second fly-through preview for globe pins.
  • Write the manifest and warm the CDN.

Risks and decisions

What could go wrong

Localizing phone audio

Placing sources from a single mono mic is ill-posed. Lean on audio-visual grounding and show users which sources are "placed" and which are "ambient".

Capture quality

Splat quality depends on how the scene was filmed. Show capture guidance (move slowly, orbit, avoid rotating in place) and fail early at SfM with a useful error.

Coordinate alignment

Splat, audio positions and geolocation must share one frame and one scale. Keep that in the manifest from the first version.

Privacy on a public globe

Faces, plates, speech and exact home locations. Offer location fuzzing (snap to about 100 m) as a default.

SATIE dependency

Keep the adapter boundary and store SATIE's raw output, so audio can be re-rendered without regenerating.

Latency

Expect 10–30 minutes end to end. Design for it with notifications, an early preview splat and visible stage progress.

Build order

Phases

  1. MVP

    Video upload, COLMAP, gsplat, web viewer with the original audio played non-spatially. Private memories only.

  2. Spatial audio

    Separation, audio-visual localization and the Web Audio viewer, with SATIE stubbed behind the adapter.

  3. SATIE integration

    Real soundscape generation, plus a reprocessing pipeline with versioned manifests.

  4. Globe and sharing

    Visibility settings, the PostGIS globe, the privacy pass, moderation and reports.

  5. Polish

    Panorama input, fast feed-forward previews, LOD streaming, and a mobile capture app with IMU/ARKit poses and better audio.
